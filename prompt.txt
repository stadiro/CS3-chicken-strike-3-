ЦЕЛЬ ПРОДУКТА (MVP, но без багов):
- Два игрока запускают проект, один хостит сервер (node), получает IP:порт
  и ссылку вида http://<IP>:<PORT> — второй открывает её в браузере и
  подключается. Оба играют 1v1 на одной карте.
- Зайти можно с двух вкладок на одной машине (для теста) и по сети (LAN/интернет).
- Матч: до 16 фрагов или 10 минут, счёт виден обоим в реальном времени.
  После конца — экран результатов с кнопкой «рематч».

ЖЁСТКИЕ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:
1. Стек: TypeScript + Node.js (Express + Socket.IO) + Three.js + Vite.
   Клиент — браузерный WebGL, никакого Electron.
2. Архитектура — СЕРВЕР-АВТОРИТАРНАЯ:
   - Сервер тикает 30 Гц: движение, коллизии, hitscan-рейкасты, урон, счёт,
     респавн, подбор оружия — всё считает сервер.
   - Клиент отправляет только намерения (input: WASD, mouse delta, fire, reload,
     use), а рендерит с интерполяцией снапшотов (буфер ~100 мс).
   - Клиент НЕ может влиять на урон/счёт/позиции — это критично для античита.
3. Никаких библиотек-фреймворков уровня «готовый шутер» (no PlayCanvas templates,
   no Ammo.js «из коробки» без обёртки). Физику делаем лёгкую: AABB-коллизии
   игрока с геометрией карты + рейкасты для выстрелов. Это быстрее и без багов.
4. Код: строгий TypeScript (strict: true), ESLint + Prettier, структура
   /client /server /shared, общие типы пакетов в /shared/protocol.ts.
   Никаких any, никаких ts-ignore.

ГЕЙМПЛЕЙ:
- Движение: WASD, прыжок (space), присесть (ctrl), мышь — обзор (pointer lock).
  Скорость/гравитация настраиваются в одном конфиге.
- Стрельба: ЛКМ. Хитскан с разбросом (spread), отдача (recoil), headshot-множитель,
  урон падает с расстоянием для дробовика (если добавишь).
- Оружие (подбирается с пола, как в fy_): Deagle, AK-47, M4A1, AWP + нож (стартовый).
  У каждого: урон, rpm, магазин, перезарядка (R), вес (влияет на скорость),
  моделька/иконка. Подбор — клавиша E рядом с оружием на полу; выпавшее при
  смерти оружие остаётся на карте.
- Респавн: через 3 секунды на базе, с ножом + пистолетом по умолчанию.
- Хедшот = x4 урон; попадание в тело = базовый; в ноги = x0.7.
- Friendly fire невозможен (игра 1v1), но сервер всё равно проверяет команды.

КАРТА (fy_iceworld-стиль):
- Симметричная арена ~40x40 м, две базы друг напротив друга, центр — ящики,
  рампы, колонны, узкие проходы. Текстуры — простые цветные (сетка/шахматка),
  освещение — directional + ambient. Карта задаётся ДАННЫМИ (JSON/TS-массив
  AABB-боксов), а не хардкодом — чтобы легко править.
- Точки спавна: по 2 на базу (случайный выбор).
- Точки спавна оружия: минимум по 2 на каждый тип, симметрично на обеих базах,
  чтобы не было преимущества стороны.

СЕТЬ И ЛОББИ:
- Сервер поднимается на 0.0.0.0:3000 (порт из env). В консоль печатает:
  локальный URL, LAN IP-адрес и ссылку вида http://192.168.x.x:3000.
- При заходе — экран «Enter name» → лобби. Если в лобби уже есть игрок —
  он видит «Ожидание второго игрока»; как только зашёл второй — обратный
  отсчёт 3..2..1 и матч стартует.
- Если игрок отключился — матч ставится на паузу, второй видит «Соперник
  отключился, ждём…». Реконнект в течение 60 секунд возвращает в матч.
- Протокол: типизированные события Socket.IO (join, input, snapshot, hit,
  pickup, round_end, score_update). Версионируй протокол (protocolVersion),
  несовпадение = отказ с понятным сообщением.
- Реализуй ping/latency-компенсацию: сервер хранит позиции за последние 200 мс
  и делает рейкаст на момент выстрела клиента (clamp по времени).

UI/HUD:
- HUD: здоровье, броня, счёт (ты — враг), таймер, название оружия и патроны.
- Киллфид (кто кого убил, каким оружием, headshot-иконка).
- Прицел — динамический (расширяется при движении/стрельбе).
- Экран конца раунда: победитель, финальный счёт, кнопка «Рематч»
  (голосование обоих).
- Настройки в отдельном меню: чувствительность мыши, FOV, громкость
  (звуки — минимум: выстрел, перезарядка, попадание, смерть; можно
  сгенерировать WebAudio-осцилляторами, чтобы не тащить ассеты).

КАЧЕСТВО / «БЕЗ БАГОВ»:
- Все ключевые модули (физика, рейкаст, урон, матч-логика) покрыты юнит-тестами
  (Vitest). Минимум: 30+ тестов, включая edge-кейсы (стрельба сквозь стену,
  двойной подбор, респавн во время перезарядки, дисконнект в момент выстрела).
- Детерминированный тик сервера (fixed timestep), никаких setInterval-костылей
  без дельты.
- Все сетевые сообщения валидируются на сервере (zod или ручные проверки):
  типы, диапазоны, частота (rate-limit на input и fire).
- Клиент никогда не доверяет своим данным: если сервер сказал «ты умер» —
  клиент сразу переходит в dead-состояние.
- Обработка ошибок: try/catch на всех сетевых хендлерах, лог с уровнями,
  процесс сервера не падает от невалидного пакета.
